# Lokaler Start – Pfarrbüro-KI V2.0 Entwicklungsstand

## 1. Voraussetzungen

- Windows 11 oder Linux
- Python 3.12
- PostgreSQL 15 oder neuer
- Zugriff auf eine isolierte Entwicklungsdatenbank

## 2. Abhängigkeiten installieren

Im Repository-Stammverzeichnis:

\`\`\`powershell
python -m pip install --upgrade pip
pip install -r pfarrbuero/requirements.txt
\`\`\`

## 3. Datenbankschema anlegen

Die Migration ausschließlich in einer Entwicklungsdatenbank ausführen:

\`\`\`powershell
psql "$env:PFARRBUERO_DATABASE_URL" -v ON_ERROR_STOP=1 -f pfarrbuero/migrations/postgres/0001_enterprise_core.sql
\`\`\`

## 4. Laufzeitrolle konfigurieren

Die Anwendung darf nicht mit dem PostgreSQL-Superuser oder Tabellenbesitzer laufen. Ein Datenbankadministrator muss eine dedizierte Login-Rolle ohne BYPASSRLS anlegen und ihr nur die für den aktuellen Vorgangskern erforderlichen Rechte geben.

Beispiel (Passwort außerhalb des Quellcodes setzen):

\`\`\`sql
CREATE ROLE pfarrbuero_runtime LOGIN NOBYPASSRLS;
GRANT CONNECT ON DATABASE pfarrbuero_dev TO pfarrbuero_runtime;
GRANT USAGE ON SCHEMA public TO pfarrbuero_runtime;
GRANT SELECT ON parish_tenants, parish_org_units, parish_users TO pfarrbuero_runtime;
GRANT SELECT, INSERT ON parish_cases, parish_audit_events TO pfarrbuero_runtime;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO pfarrbuero_runtime;
\`\`\`

Das Login-Passwort wird über einen Secret Store bzw. eine sichere Betriebssystem-Konfiguration verwaltet. Es gehört nicht in Git, eine .env-Datei im Repository oder die EXE.

## 5. Testmandant und Benutzer

Vor dem Start müssen ein Mandant, eine Organisationseinheit, ein aktiver Benutzer und eine aktive Mitgliedschaft mit Rolle vorhanden sein. Die Rolle muss mindestens case.read besitzen. Zum Anlegen von Vorgängen wird zusätzlich case.create benötigt. Die jeweilige UUID wird dem angemeldeten Benutzer nach erfolgreicher Authentifizierung serverseitig zugeordnet. In dieser Entwicklungsstufe wird diese Zuordnung noch über Umgebungsvariablen simuliert. Die Rolle read_only kann lesen, aber keine Vorgänge anlegen. Vorgänge mit pastoral_secret werden nur mit pastoral_secret.read angezeigt.

## 6. Entwicklungsmodus starten

\`\`\`powershell
$env:PFARRBUERO_DATABASE_URL = "postgresql://pfarrbuero_runtime:<SECRET>@localhost:5432/pfarrbuero_dev"
$env:PFARRBUERO_TENANT_ID = "<TENANT-UUID>"
$env:PFARRBUERO_ORG_UNIT_ID = "<ORG-UNIT-UUID>"
$env:PFARRBUERO_USER_ID = "<USER-UUID>"
python pfarrbuero/app.py
\`\`\`

Ohne \`PFARRBUERO_DATABASE_URL\` startet die GUI ausdrücklich im lokalen Demo-Modus mit SQLite. Ist PostgreSQL konfiguriert und nicht erreichbar, zeigt die Anwendung einen Fehler und fällt nicht auf Demo-Daten zurück.

## 7. Abgrenzung

Dieser Stand ist ein technischer Entwicklungs-/Integrationsnachweis. Es fehlen insbesondere:
- OIDC/SSO und echte Benutzeranmeldung
- serverseitige Rollen- und Berechtigungsprüfung vor jeder Aktion
- sichere Mandantenauswahl aus der authentifizierten Sitzung
- Admin-Oberfläche für Mandanten, Organisationseinheiten und Benutzer
- Datenschutz- und Sicherheitsabnahme für reale kirchliche Daten

Keine Echtdaten, Sakramentenregister oder Seelsorgeinformationen in dieser Entwicklungsfassung verwenden.
